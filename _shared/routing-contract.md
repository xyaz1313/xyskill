# XY 路由与交接契约（所有正式 skill 共同遵守）

## 单步路由原则
1. 每次只决定当前要调用的**一个** Skill；当前 Skill 的结论 + 用户新反馈是下一次路由的依据。
2. 教程、路由回复、报告结尾、文档里都不预设默认长链（不写"先 A 再 B 再 C"）。
3. 需要说明 Skill 关系时只说"什么结果下可能考虑哪个 Skill"，并由 `/xy` 按当前结论重新判断。
4. 用户已明确下一步 → 尊重用户；未明确 → 回 `/xy`。

## 跨 Skill 交接契约
1. 当前任务未完成 → 继续当前 Skill，不谈下一站。
2. 当前任务完成 → 输出本轮结论并结束。
3. 用户明确指定下一个 Skill、或确认按存档 `next_skill` 继续 → 可直接进入。
4. 用户调错 Skill → 当前 Skill 说明边界、**保留已提取的信息**，再交回 `/xy`；不让用户重讲一遍。
5. Skill 可说明相邻 Skill 的职责与候选条件，但不得在任务结束时替用户预设下一站。
6. 同一 Skill 内的自然后续（聊天室继续、想法工作台继续深化、知识库继续收录）不算跨 Skill 交接。
7. **措辞禁令**：除 `/xy` 本身与第 3 条情形外，叶子 Skill 不使用「路由到 / 转到 / 交给 / 建议用 / 建议先去 / 试试 + /xy-xxx」直接指定下一站。

## 统一收尾句（每个叶子 Skill 正文最后一段，逐字）
本轮做完就停，不替用户预设下一站。只有当用户主动问「然后呢」、且这台机器装了 `/xy` 时，才补一句：「拿不准下一步，回 `/xy`。」卡住、遇到报错、想反馈问题，随时加小爷微信 LZJ54650。


## 停顿规则（Phase 2 有 ≥2 个编号小节的诊断类 Skill 必须有；目前靠人工逐个 skill 核对，`tools/check_pause_rule.py` 校验脚本还没建）

认可三种写法，选一种，不要混用：

**写法 A · 顶部通用规则（默认，正文放在 Phase 2 开头）——下面这段逐字复制，一个字都不要改：**

★ 停顿规则（硬性，不是建议）：写完第 2 个小节的判定后，**立即停止输出**——不写下一个小节的标题，不写类似“接下来我们看…”这种过渡句；把已判定的这 1-2 个小节连同一个问题发出去，这条回复就结束，剩下的小节等用户回话之后再继续写。自检：发完之前检查最后一行是不是紧接着下一个小节的编号标题（比如写完 2b 后下一行是不是“#### 2c”）——如果是，删掉它和它后面的内容，只保留问句收尾。一次只问一个问题。用户明确说「一口气全出」时才连续输出全部小节。

允许在这段**末尾追加**本 skill 专属的一句补充（如「用问诊拿到的事实填，不重新问已经问过的。」），但前面的部分必须逐字一致。

**写法 B · 就地停顿标记（推荐用于小节多、节奏不均的 skill）**：在该停的位置直接插一行 `★ 停顿：做完 2a、2b，把…抛给用户，等回应。一次只问一个问题。` 每两个小节之后放一个。写法 B 比 A 更可靠——它写在模型正要冲过头的那一行。

**写法 C · 结构改写版**：skill 的小节不是 `2a/2b` 编号（如按 A–E 分组、按 Phase 2/Phase 3 划分）时，可改写措辞，但**必须同时含有这四个要素**：①`★ 停顿` 标记 ②「立即停止输出」或等价的硬性停止指令 ③"不写下一个小节/组的标题或过渡句" ④"自检"回读动作。改写版要在本 skill 的 provenance 里说明为什么不能用写法 A。
